# 🧱 Архитектура ИБ-ориентированной суверенной ИИ-автоматизации

Я проектирую **не просто автоматизации, а регуляторно-устойчивые AI-системы**, в которых информационная безопасность заложена на этапе проектирования.  
Этот документ описывает архитектурные принципы, лежащие в основе всех моих решений для юридических и земельных процессов в Российской Федерации.

---

## 🔐 Основополагающие принципы

### 1. **Security by Design (Безопасность от проектирования)**
- Анализ угроз проводится **до** написания первой строки автоматизации  
- Использую методологию **LINDDUN для ИИ-систем** и адаптированную модель **STRIDE**  
- Каждый компонент оценивается на предмет конфиденциальности, целостности и доступности

### 2. **Zero PII (Нулевая обработка ПДн)**
- Персональные данные **исключены архитектурно**, а не фильтруются на входе  
- Все запросы и шаблоны формулируются в **обезличенной форме**  
- Даже гипотетические сценарии с ПДн не рассматриваются в проектировании

### 3. **Суверенность и Data Residency**
- Вся инфраструктура размещается **на VPS в Российской Федерации**  
- Генеративные модели используются **только через официальные API с отключённой персонализацией**  
- Данные **никогда не покидают территорию РФ** — ни при обработке, ни при хранении

### 4. **Сквозная аудитуемость**
- Каждая автоматизация генерирует **аудит-след**: timestamp, тип операции, источник, результат  
- Логи хранятся локально и доступны для проверки **без зависимости от внешних сервисов**  
- Архитектура поддерживает требования **ФЗ-152 (ст. 18)** и рекомендации **ФСТЭК**

### 5. **Минимизация поверхности атаки**
- Компоненты изолированы через **Docker**  
- Сетевой трафик сегментирован, внешний доступ ограничен  
- Принцип **минимальных привилегий** применяется ко всем сервисам и пользователям
- [Пользователь]
│
▼
[Запрос без персональных данных]
│
▼
[n8n workflow (self-hosted, РФ)]
├───► [Cursor AI / LLM через прокси]
├───► [PostgreSQL с row-level security]
└───► [Loki/Grafana — логирование]
│
▼
[Результат + метаданные аудита]


> Все компоненты развернуты в **изолированной среде** на VPS в РФ.  
> Нет подключения к SaaS-сервисам за пределами РФ.  
> Нет хранения или кэширования пользовательских данных.

## 🛠 Используемые ИБ-инструменты и практики

| Направление               | Инструменты / Подходы                     |
|--------------------------|-------------------------------------------|
| Анализ угроз              | LINDDUN, STRIDE, DREAD                    |
| Управление секретами      | HashiCorp Vault                           |
| Изоляция и развёртывание  | Docker, Docker Compose                    |
| Защита транзитных данных  | TLS (Traefik), HTTPS-only                 |
| Защита данных на диске    | LUKS, шифрование на уровне ОС             |
| Сканирование уязвимостей  | Trivy (образы), Clair                     |
| Аудит и мониторинг        | auditd, Loki + Grafana                    |
| Контроль доступа          | RBAC в n8n, минимальные привилегии        |

## 📜 Соответствие нормативным требованиям

- **ФЗ-152**: соблюдение статей 3, 6, 18 — архитектурно  
- **Рекомендации ФСТЭК**: применение мер защиты уровня 1–2  
- **Требования ЦБ РФ**: для проектов в финансовом секторе — дополнительная сегментация и аудит  
- **GDPR-подобные практики**: хотя не применяется напрямую, принципы privacy by design используются как best practice
